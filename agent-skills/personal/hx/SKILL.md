# hx

hunk の差分で引っかかった箇所を調べ、解説を hunk のインラインコメントとして書き戻す。
解説はターミナルではなく差分の横に置く。ユーザーは hunk から視線を外さずに読む。

ARGUMENTS に追加の指示（「呼び出し元まで追って」など）があれば、調べ方と書き方に反映する。

TUI はユーザーのもの。`hunk diff` / `hunk show` などの対話コマンドは実行せず、`hunk session *` だけを使う。

## 1. 対象を決める

`hunk session comment list --repo . --type user --json` を実行する。

- 1件以上あれば、それら全部が対象。本文が `?` だけでも空でも「この箇所を解説してほしい」という依頼として扱う。具体的な問いが書かれていればその問いに答える。
- 0件なら `hunk session context --repo . --json` の `selectedFile` と `selectedHunk` が指す1箇所を対象にする。
- セッションが無ければ hunk の起動を促して終わる。勝手に起動しない。

## 2. 調べる

`hunk session review --repo . --include-patch --json` で対象箇所の差分を取る。

差分だけで答えが確定することは稀。実ファイルを読み、呼び出し元・定義・型・テストまで追う。差分の見た目からの推測で書かない。
追っても確定できないことは、確定できないと書く。それらしい説明で埋めない。

## 3. 書き戻す

対象1件につき1回 `comment add` を実行する。

```bash
hunk session comment add --repo . --file <path> --new-line <n> \
  --summary "<結論>" \
  --rationale "<補足があれば>" \
  --author "explain"
```

コメントは折りたたまれず全展開で差分に割り込む。日本語と半角英単語が混ざると1行40字程度で折り返すので、字数はその2〜3倍の行数になって差分を画面外へ押し出す。上限は厳守する。

- 行は対象と同じ位置を指す。user コメントなら `newRange[0]`、削除側にしか無い場合は `--old-line`。カーソル起点なら hunk の先頭行。
- `--summary` に問いへの答えを置く。60字以内。動作のなぞりで終わらせない。
- `--rationale` は summary で足りないときだけ付ける。200字以内。根拠の位置は `src/foo.ts:120` 形式で、結論を支える2〜3箇所に絞る。調べた内容を全部は書かない。
- 1件目にだけ `--focus` を付け、ユーザーの視点をそこへ運ぶ。
- 書き終えたら、対応する user コメントを `hunk session comment rm --repo . <noteId>` で消す。残すと次回また対象になる。

`comment apply` のバッチは使わない。payload のキーが docs（`newLine`）と実装（`side` + `line`）で食い違っている。

## 4. 報告

ターミナルには「N件に解説を付けた」と対象箇所の一覧だけを短く出す。解説本文は再掲しない。

# deep-review

レビューの観点は既存 skill に任せ、この skill は並列実行と独立検証を配線する。

## Phase 1 — 並列レビュー

次に挙げる各 skill または fallback 観点ごとに general-purpose subagent を1体起動する。利用可能な同時実行枠まで並列に起動し、枠を超えるものは完了した枠へ順次起動する。

- /code-review high。利用できるときだけ起動する。利用できず、コード以外の差分が含まれるときは、その非コード差分を general-purpose subagent に正しさ・契約整合性・退行の観点でレビューさせる
- /prune-review
- /adversarial-review
- /security-review — 差分が、攻撃者が制御できる入力、信頼境界、認証・権限、秘密情報・ログ、暗号・乱数、デシリアライズ、シェル補間、パス・クエリ・テンプレート生成、ネットワーク・Web 境界、依存関係・lockfile のいずれかに関わるときだけ起動する。メモリ安全性、競合・TOCTOU、リソース枯渇は、攻撃経路またはセキュリティへの影響を具体的に示せる場合だけ対象にする。利用できなければ、general-purpose subagent に同じ範囲をセキュリティ専門でレビューさせる

差分は切り出して渡さず、対象の指定（未コミット差分、HEAD からの差分など）だけを渡す。各 subagent に差分を取得させ、契約を理解するために必要な周辺だけを確認して具体的な候補を立てさせる。相互依存しない読み取り・検索はまとめて実行させ、候補の裏取り以外で探索範囲を広げさせない。

各 subagent には最終的な指摘だけを返させる。各候補に `file:line`、壊れる入力・経路または不要と判断する根拠、Phase 2 で確認すべき対象（symbol、command、ツールのデフォルト挙動など）を付けさせる。探索経過、良い点、修正案は返さず、候補数に上限を設けない。1回の応答に収まらなければ全候補を一意な一時ファイルに書き、絶対パス、総件数、完了マーカーだけを返させる。一時ファイルの完了マーカーを確認してから Phase 2 へ進み、読み終えたら消す。修正はさせない。

## Phase 2 — 検証

候補が無ければ Phase 2 を省略する。同一の根本原因と実行経路に属する候補を重複排除し、同じ file、symbol、call path に属する候補は1体の fresh subagent でまとめて検証させる。Phase 1 の subagent は検証に再利用しない。依存領域が独立している場合か、コンテキスト上限に達する場合だけ複数体に分ける。
検証の subagent は model を指定しない（セッションモデルを継承させる）。false positive を殺す精度が一番効く場所なので、ここは落とさない。

- 正しさ・セキュリティの指摘 — コードパスを実際に追う。必要なら既存テストや再現コードを実行する
- 過剰・冗長・残骸の指摘 — 使用箇所の検索、ツールのデフォルト挙動の確認で裏取りする

検証で working tree を変更したまま残さない。一時ファイルを作ったら消す。
再現・裏取りできなかった指摘は落とす。

## 出力

検証を通った指摘だけを、file:line と検証根拠つきで返す。修正はしない。
何も残らなければ「指摘なし」と書く。ひねり出さない。

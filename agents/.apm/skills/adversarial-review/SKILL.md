# adversarial-review

この差分の作者はマージしたがっている。この skill の役割は作者ではなくレビュアー — マージすべきでない理由を見つけることだけを仕事にする。
prune-review が設計・冗長・残骸を診るのに対し、こちらは正しさと堅牢性の欠陥を recall 重視で洗い出す。

## 前提

- レビューは差分を起点にする。実装の意図や「動くはず」という前提は判断材料にしない。コードが実際に何をするかだけで判断する。
- 良い点は書かず、動く証明もしない。指摘するだけで、修正はしない。

## 対象の決め方

呼び出し元から比較元・対象の版・範囲が指定されていればそれを使い、下記の既定の選択で上書きしない。指定がなければ依頼から対象を決める。

- PR → PR の base と head の差分
- ブランチ・マージ前 → 基準ブランチとの差分。無関係な未コミット変更があっても範囲を切り替えず、対象外の変更があることだけ伝える
- staged・コミット予定 → `git diff --cached`
- パス指定 → そのパス。ファイル全体か差分かは依頼から判断し、読み取れなければ確認する
- リポジトリ全体 → 明示された場合だけ

依頼に範囲の指定がなければ、次の既定の手順で決める。一意に決まらない場合だけ確認する。

1. `git status --porcelain` で staged・unstaged・未追跡を確認する。差分の有無を `git diff HEAD` だけで判断しない。
2. 未コミット変更があれば、`git diff HEAD`（作業ツリーの最終状態）と未追跡ファイルの内容を対象にする。未追跡ファイルは直接読み、`git add -N` など index を変更する方法は使わない。`git diff HEAD` が空でも status に変更があれば staged と unstaged が相殺している。`git diff --cached` と `git diff` を個別に確認し、コミット予定の内容と最終状態のどちらを見るか依頼から決め、決まらなければ確認する。
3. 未コミット変更がなければブランチ差分。比較元はユーザー指定、PR の base、upstream、リモートのデフォルトブランチ、ローカルの基準ブランチの順で確認し、`origin/main` に固定しない。一意に決まらなければ確認する。

失敗と例外を区別する。

- `git rev-parse --verify HEAD` が失敗するなら初回コミット前であり、全ファイルを新規として扱うか確認する。
- 比較コマンドが失敗したら差分なしと混同せず、失敗として報告する。
- 差分が空なら、対象がないことを伝えて終える。リポジトリ全体へ自動的に広げない。

レビュー中に対象が変わったことを検知したら、指摘の位置と再現性を再確認する。

## 手順

1. 下記の観点で、壊れる入力・経路を探す。差分だけで判断できないものは、呼び出し側・周辺まで読んで契約を確かめる。
2. 各指摘を、該当箇所の `file:line` と「どの入力・経路で、なぜ壊れるか」をセットで返す。

## 観点

作者を擁護しない。動く根拠ではなく、動かない経路を探す。

- **ライフタイム / 資源** — use-after-free、二重解放、非同期解放と drop の順序、リーク。
- **境界・数値** — 境界値、負値、オーバーフロー / アンダーフロー、ゼロ除算、丸め方向。
- **エラーパス** — 失敗時・部分失敗時の状態、握り潰し、途中終了でのリソース残留。
- **並行性** — データ競合、デッドロック、前提が崩れる割り込み。
- **評価順序・副作用** — 正格 / 遅延評価の取り違え、短絡の有無、副作用の順序。
- **契約違反** — 呼び出し側の前提（null 非許容・呼び出し順・不変条件）を破る変更。
- **退行** — 既存の入力で挙動が変わる箇所。

## 出力の作法

- 各指摘は `file:line` と「どの入力・経路で、なぜ壊れるか」を必須にする。この2つを書けない指摘は出さない。
- recall 重視だが、経路を示せない当てずっぽうは出さない。ひねり出さない。
- 修正方針は1行添えてよい。

# 日本語UXライティング

## 用語と文章

- 同じ対象と操作には同じ名前を使う。既存の用語集や隣接画面を確認し、「保存」「登録」「申請」「公開」などを実際の結果に合わせて選ぶ。
- 利用者が知っている言葉を使う。内部の実装名や社内略語を画面に出さず、必要な専門用語は意味を保ったまま説明する。
- 一文で伝える内容を絞り、長い前置きや過剰な敬語を減らす。短縮しても条件、対象、否定、操作の結果は残す。
- 漢字・ひらがな・カタカナは読みやすさと既存の表記に合わせる。難しい表記を避ける一方、すべてをひらがなにして意味の区切りを失わせない。
- 説明文では助詞を残し、誰が何をするかを明確にする。ラベルは短くてもよいが、意味が曖昧になる省略は避ける。
- 日本語の見出しに英語のTitle Caseを適用しない。英数字、日付、単位、句読点の表記はプロダクトの規約に合わせる。

## 操作と入力を説明する

- ボタンは押した結果がわかる動詞で表す。周辺で対象が明らかな場合は「保存」などの短いラベルでよい。確認画面では「はい」「OK」だけに頼らず、実行する操作を示す。
- リンクは行き先の内容を示す。「こちら」だけをリンクにせず、対象のページ名や情報をリンクテキストに含める。
- 入力欄には常に見えるラベルを付け、必要な形式や制約は近くの説明に置く。入力例やプレースホルダーだけで必須の情報を伝えない。
- 必須・任意、許容する文字数や形式は実際のバリデーションに合わせる。「半角のみ」などの制限を根拠なく足さない。
- 表示する文言とアクセシブルな名前を対応させる。アイコンだけの操作には名前を付け、読み上げ名にも画面で見える文言を含める。

次は文脈と仕様が一致する場合の書き換え例。固定のテンプレートとして適用しない。

| 場面 | 曖昧な表現 | 内容が伝わる表現 |
| --- | --- | --- |
| 下書きの保存 | OK | 下書きを保存 |
| 氏名が未入力 | 入力が不正です | 氏名を入力してください |
| 手順へのリンク | こちら | 請求書の作成手順 |

## エラーと状態

- エラーは利用者に起きたこと、判明している原因、対処を伝える。画面の文脈で自明な情報は省けるが、解決に必要な情報を省かない。
- 入力エラーは対象の欄と修正方法を示す。利用者を責めず、入力済みの内容を保ち、修正できる場所へ案内する。
- 原因不明の失敗を「通信エラー」と決め付けない。保存結果が不明な場合に「保存されていません」と断定したり、重複実行の可能性を確認せず再試行を勧めたりしない。
- 成功の表示は処理の完了と一致させる。処理の受付や開始を完了と表現しない。待ち時間や進捗率は実際に取得できる情報だけを使う。
- 一覧のデータなし、検索結果なし、取得失敗、権限不足を別の状態として扱う。初回なら作成、検索なら条件変更など、実際に可能な次の操作を示す。
- 項目の未設定と、対象外・非公開・取得できない値を混同しない。空白や記号の意味は既存の表示規約とそろえる。
